## 任务 1 · 每日收尾（18:00）

1. 执行 `python3 "D:/我的工作台/量化/投资工作台/invest_workbench_daily.py"`。
2. 脚本自动完成：服务与端点探活、Cookie 校验、快照新鲜度检查；交易日则本地取数、重分类、经 TAT 推云端并重启服务。
3. 读取 `.cache/daily_unified.log` 末尾，确认退出码 0、巡检结论、持仓截至当日、资料库覆盖成功。
4. 若出现「Cookie 失效」「持仓未更新」或退出码 2，显著告警人工续期；服务探活异常则提示服务器可能宕机；周末跳过同步属正常。
5. 同一次运行内继续生成真实持仓概览：调用同花顺账本 MCP 工具取持仓、当日盈亏与区间盈亏，写入 `.cache/` 下三个 JSON，再运行 `daily_tzzb_report.py`。
6. 汇总汇报：运行日期、巡检结论、是否交易日、同步结果、总市值、总盈亏、仓位最高一只、异常提醒。
7. 两段相对独立：数据同步失败不阻断持仓概览；MCP 返回 401 时如实提示重新授权，不得编造数据。

## 任务 2 · 小时级探测（工作日每小时）

1. 执行 `python holdings_probe.py --scope core`：非交易时段打印 SKIP 秒退；交易时段抓核心池持仓，经 TAT 推服务器合并进 `holdings_snapshot.json`。
2. 执行 `python nav_hourly_probe.py`：非交易时段打印 SKIP；交易时段探测最新净值日，若有推进则全量抓 74 只、推服务器、重建 `pool_daily`、重启服务并更新基准。
3. 分别汇报两项的 SKIP/执行结果；出现 `NEED_COOKIE`、`BLOCKED`、风控、`TAT 不可用` 时原样报错。
4. 严禁伪造成功；不改脚本、不删除锁文件；`NEED_COOKIE` 时提示重抓雪球 Cookie 写回 `xq_cookie.txt`。

## 运行依赖与注意事项

- Windows + Git Bash + Python 3.10 以上（本机 3.13.14），四个核心脚本均只用 Python 标准库。
- 用户级环境变量 `TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY` 必须存在；重启 WorkBuddy 后生效。
- 账本 MCP 需在 WorkBuddy 中完成同花顺投资账本授权（股票账户 `151780533`、基金账户 `179522298`）。
- 必需目录：`D:/我的工作台/02.输出区`、`.workbuddy/memory`、`投资记录`、`量化/雪球组合监控`。
- 调度器对 `FREQ=HOURLY` 不按 `BYMINUTE` 生效，第 2 项的实际分钟点不固定；脚本在非交易时段会自行 SKIP，不影响数据正确性。
- 双机切换顺序：**先启新机并验证 → 暂停旧机 4 项原任务 → 观察一天 → 旧机才可借出**。两台同时运行会重复推送、重复生成报告。
- 雪球 Cookie 通常约 7 天过期，借出时间较长时可能中途失效，页面持仓会停更，需人工续期。
