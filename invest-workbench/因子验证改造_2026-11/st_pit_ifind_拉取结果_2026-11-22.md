# iFinD 时点化 ST 数据拉取结果

> 拉取时间：2026-11-22 ｜ 负责人：C（数据工程） ｜ 数据源：同花顺 iFinD 专业数据源（`get_security_indicators`）
> 目的：为历史绩效回测提供逐日 ST / 风险警示状态，替代 `exclude_unbuyable.json` 的当前快照
> 边界：本次只新增文件，未改动 `exclude_unbuyable.json`、`exclude_st_pit.json`、引擎代码，未部署

## 一、结论先行

1. **可行，且已落地。** iFinD 的「戴帽摘帽时间」字段提供了带日期的戴帽与摘帽事件序列，可解析为左闭右开的 ST 区间。6142 个代码全部拉取成功，失败 0 只。
2. **覆盖优于现有本地名单。** 1319 只股票有 ST 区间，比本地 `exclude_st_pit.json`（821 只曾用名含 ST）多出 499 只，多出来的基本是本地名单漏掉的退市股。本地名单里的 821 只，iFinD 命中 820 只。
3. **面板股票池 100% 覆盖。** `panel_v3.pkl` 的 5812 只全部在池内，逐只查过。
4. **已知缺口一处，已量化并标记。** iFinD 的字段对 225 只股票漏掉了最后一次「摘帽」事件，区间终点因此未知。这 225 只里 47 只在面板内（主板 28 只、沪市 19 只），178 只是北交所与退市股。处理方式是保守保留开放区间并打 `end_missing: true` 标记，没有用估算日期填充。
5. **与现有快照的差异可解释。** `exclude_unbuyable.json` 的 665 只里，253 只在时点数据里「今天不是 ST」，这 253 只全部已退市；另有 24 只时点数据判今天为 ST 而快照里没有，这 24 只全部属于上面那类终点缺失的股票。
6. **曾用名兜底没有产生新增标记。** 本地曾用名名单里唯一没有被 iFinD 戴帽字段命中的是 001267 汇绿生态。逐只核查后确认该股 iFinD 曾用名为空、A 股上市日为 2021-11-17；akshare 里的 ST华信、*ST华信 属其新三板时期，A 股上市后从未戴帽，因此不该标记。团队之前提到的 600149 廊坊发展实测并不为空，iFinD 能返回完整的两段区间。

## 四、区间解析规则

1. 遇到戴帽事件（ST 或 *ST）开一个区间，区间起点取最早一次戴帽。
2. **「摘*」只摘掉星号，风险警示并未结束，区间不关闭。** 这一条容易踩坑：`*ST → ST` 是两段风险警示，中间的摘星号事件不能当作区间终点。早期版本按普通摘帽处理，会把 600080 ST金花 2007 到 2012 这 5 年半的风险警示拆成两段。
3. 「摘帽」才关闭区间，终点取摘帽日。
4. 末位仍是戴帽且无摘帽事件时，终点取摘牌日期；无摘牌日期则区间开放至今，终点记 null。
5. 区间按左闭右开处理，`[start, end)` 期间处于风险警示状态。

区间自检结果：起点不早于终点的区间 0 个，区间相互重叠的 0 个，终点晚于摘牌日的 0 个。区间年限中位 1 年，均值 1.7 年，最长 27 年。

## 六、与本地两份名单对比

### 6.1 与 exclude_st_pit.json（821 只曾用名含 ST）

| 项 | 数值 |
|---|---|
| 曾用名含 ST 且 iFinD 有区间 | 820 |
| 曾用名含 ST 但 iFinD 无区间 | 1（001267 汇绿生态，经核查为新三板时期历史，A 股从未戴帽，不标记） |
| iFinD 有区间但曾用名名单没有 | 499 |

多出的 499 只几乎全是已退市股票，例：000003 PT金田A、000004 国华退、000005 ST星源、000013 *ST 天发、000015 *ST 华资、000016 *ST 深康佳、000018 *ST 神城、000023 ST 中达、000033 新都退、000038 *ST 科]。本地名单用 akshare 名称变更接口扫描当时的在册代码生成，退市股不在扫描范围内，所以漏掉了这一大块。iFinD 这 499 只带精确日期，是本次数据相对本地最实质的增量。

### 6.2 与 exclude_unbuyable.json（665 只当前 ST 快照）

| 项 | 数值 |
|---|---|
| 两边交集（今天都是 ST） | 412 |
| 快照有、时点数据今天没有 | 253，全部已退市 |
| 时点数据今天有、快照没有 | 24，全部属于终点缺失类 |

这 253 只已退市股在当前快照里被当作不可买标的剔除，用当前快照回测历史时会凭空少掉一批 2018 年前正常交易的股票。时点数据把它们的 ST 区间精确定位到了各自的历史区间内。

### 6.3 终点缺失的 225 只

| 分布 | 数量 |
|---|---|
| 总数 | 225 |
| 在 panel_v3 内 | 47（0 字头 28 只，6 字头 19 只） |
| 不在面板内（北交所与退市股） | 178 |

成因：iFinD 的「戴帽摘帽时间」字段对某些股票只记录了戴帽事件，漏掉最后一次摘帽事件。例如 000792 盐湖股份字段只有 `*ST:20190430`，但「是否属于风险警示板」返回否，说明它后来摘过帽，摘帽日期在字段里查不到。

处理方式：保留为开放区间并标记 `end_missing: true` 与 `risk_board_now: 否`。这是保守选择，保证不会在它实际处于 ST 的期间把它买回，代价是这 47 只面板内股票从最后一次戴帽日起被持续剔除。

替代方案已评估并放弃：iFinD 公告检索能搜到撤销风险警示的公告，但语义检索返回的多数是近期无关公告，历史那一条埋在里面，且搜到的多为「申请撤销」的议案日期而非交易所批准生效日，日期不可靠，不做自动填充。

## 七、数据质量与局限

1. **终点缺失 225 只**，已在输出里逐只标记，不做估算填充。
2. **曾用名兜底无新增标记**：本地名单唯一未命中的 001267 汇绿生态，iFinD 曾用名为空、A 股上市日 2021-11-17；akshare 里的 ST华信、*ST华信 是新三板时期，A 股从未戴帽。已完成全量空字段扫描，候选 4824 只，其中曾用名含 ST 为 0 只、曾用名非空 1128 只，未发现漏网股票，最终 `name_hint_only_count = 0`。
3. **接口限流**：3 进程并发会触发限流，接口返回空表。已改为单进程、10 只一批、每批间隔 1.1 秒、空表即失败重试并退避（连续 3 次失败暂停 45 秒）。实际运行失败 0 只。
4. **批量上限**：单次超过 10 只会静默截断返回行数。主脚本加了内容完整性复核，抓到 6 只疑似截断并单独重取，修正 0 只，说明这 6 只是数据本身如此，不是截断。
5. **边界约定**：摘帽日当天不再算 ST，即区间为 `[start, end)`。若认为交易所公告日与生效日之间还有风险警示状态，把终点后移一日即可，解析脚本里只需改一处。
6. **未覆盖的退市清算价、三板价**：本次只解决 ST 状态，不涉及退市后的清算价格。

## 八、使用建议

1. 回测里把 `exclude_unbuyable.json` 的静态全期剔除，换成按交易日查 `st_pit_intervals.json` 的区间判定：`start <= t < end` 即该股当日处于风险警示，当日不可买。
2. `end_missing: true` 的 47 只面板内股票，建议在全期剔除或按你自己的保守假设处理，并在回测报告里注明这个口径，避免与历史结果对比时出现无法解释的差异。
3. 用 `st_pit_crosscheck.json` 复核：新旧口径的差异应集中在第三节列出的 253 只退市股与 24 只终点缺失股上，若出现别的差异说明用法有误。
