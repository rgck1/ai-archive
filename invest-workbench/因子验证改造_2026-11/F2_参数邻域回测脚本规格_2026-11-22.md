## 〇、结论先行

1. F2 是周频择时仓位因子，与 cs_flex 股票横截面选股引擎不同。建议独立新建 `f2_backtest.py`，复用 `xbx_engine.metrics` 并把年化固定为 √252。
2. 核心结构：日线数据聚合成周线产生信号，信号在周最后一个交易日收盘后生成，下一周首个交易日收盘成交，其余交易日逐日盯市。
3. 参数网格 75 组（买阈值 5 × 卖阈值 5 × MA 周期 3），每组都跑全样本与样本外，再叠加 100 次安慰剂。
4. 脚本必须自检四项硬门槛：样本外不劣于买入持有、回撤更小、安慰剂 pct ≥ 0.90、参数邻域多数组合有效。结果写入固定 JSON 结构。

**字段实况（C 已扫表头确认，无需实跑）**：

|---|---|---|
| 39 个腾讯 qfq | 7 | date、open、high、low、close、volume、amount |

要点：39 个 qfq 文件无 pct_chg、无 turnover。涨跌停代理统一用 `close.pct_change()` 自算，复权因子为全局常数，收益率序列与 hfq 一致，此算法安全。停牌只用 `volume == 0`。`turnover` 在 qfq 中缺失，禁止当可用列。9 只东财文件的 raw 与 hfq 两份都含 pct_chg 与 turnover，做 raw 对照可直接用。

补充说明：

- **偏离率在 qfq 与 hfq 上数学等价，可以使用**。偏离率 `dev = (close − MA(close)) / MA(close)` 是同一序列内部的比值。前复权价 = 后复权价 × 全局常数因子 k，MA(qfq) = k × MA(hfq)，分子分母的 k 约掉，dev 不变。因此 39 个 qfq 文件算出的偏离率与 hfq 结果一致，F2 回测结果有效。文档表述须准确：这 39 个是前复权，不得称为后复权；跨源拼接绝对价仍禁止，本规格不拼绝对价，只用同一标的内部序列。
- 复权对照恢复可行。39 个 qfq 文件可用于前复权对照，9 只的 `etf_raw_*.csv` 可用于不复权对照。此前"本机做不到对照"的结论作废。F2 主口径用复权序列（hfq 或 qfq 均可，dev 等价），对照口径选同标的 qfq 与 raw 各跑一次，差异写入报告。
- F1 折溢价只能用不复权价（见主设计文档 2.7 节）。F2 收益回测用复权价，禁止用不复权价算 F2 均线，分红除权会造成价格假突破。两者不可混用。
- **起点不齐，必须逐标的写死起始日**。48 只共 22 个不同起点，最早 510150 消费ETF沪 2016-05-09，最晚 159611 电力ETF 2022-01-07，聚集在 2016-05-19（8 只）、2018-01-02（7 只）、2020-05-19（11 只）。禁止用统一起始日，否则早期数据会被前值填充污染。每只标的数据起点取该标的 CSV 首行日期。
- 预热口径：90 周 = 450 交易日，加 1 年缓冲 244 交易日，合计 694 交易日。信号日 = 该标的起点 + 694 交易日。**纳入标准：信号日 ≤ 2022-12-31**，保证样本外 2023-01-01 起留够 3 年以上。按 C 核算，48 只中 27 只满足，21 只剔除。不满足示例：511380 信号 2023-02-16；512170、512480、512710、159995、159996、512290、512720、515000、515030、515080、515180、515210、515220、515880 均为 2024-06-13；515790 2025-01-14；516160 2025-03-10；159870 2025-03-28；159865 2025-04-02；516110 2025-06-04；159611 2026-02-03。
- 标的池：主标的用 510880 红利ETF（起点 2016-05-19，信号 2020-08-05）与 512890 红利低波ETF（起点 2019-01-18，信号 2021-12-01），两只都过纳入标准。宽基对照用 510300、510500、510050、159915、159907，均起点 2018-01-02、信号 2020-11-12，全部满足。红利类 515080 与 515180 起点 2020-05-19、信号 2024-06-13，不满足，剔除。注意 510150 消费ETF沪与 159939 信息技术ETF 属行业类，不得当宽基。
- 幸存者偏差：48 只均为当前在交易标的，无历史退市清盘清单，存在幸存者偏差，须在报告中标注。
- 涨跌停与停牌字段 CSV 缺失，按上述代理规则推断：停牌用 `volume == 0`，涨跌停用 `close.pct_change()` 自算（C 已确认 39 个 qfq 文件无 pct_chg 列）。若推断不可靠，F2 的不可成交顺延退化为记录缺失说明，不得据此判交易可执行。

## 二、参数网格

```python
BUY_TH_GRID   = [-0.05, -0.04, -0.03, -0.02, -0.01]   # dev <= buy_th 触发分批买入
SELL_TH_GRID  = [ 0.06,  0.07,  0.08,  0.09,  0.10]   # dev >= sell_th 触发分批卖出
MA_WINDOW_GRID = [60, 90, 120]                          # 周线简单均线窗口
BATCH_FRAC    = 0.20                                    # 每批投入可用资金比例
MAX_BATCHES   = 5                                       # 最多分批次数
COOLDOWN_WEEKS = 1                                      # 相邻触发最小间隔（周）
SIGNAL_MODE   = 'cross'                                 # 'cross' 穿越触发，'level' 水平触发
```

- 组合总数 5 × 5 × 3 = 75。基准参数 `buy_th=-0.03, sell_th=0.08, ma_window=90`。
- `cross` 模式：要求 dev 本周期下穿买阈值（或上穿卖阈值）才触发，避免同一信号重复扣款。`level` 模式：只要 dev 在阈值外且满足冷却期即触发，需配合 COOLDOWN_WEEKS 使用。默认 `cross`。
- 买阈值与卖阈值不对称（卖阈值更高）是原因子设计，网格保留该不对称，不做对称化。

## 四、成交与净值口径（A 实现时逐条核对）

1. 周线聚合：`resample_weekly` 只纳入已完成周。周五收盘后才计算当周 dev 与目标仓位。
2. 成交时点：周 t 的目标仓位在周 t+1 首个交易日收盘执行。执行日按当日收盘价调仓，扣除佣金与滑点。
3. 日间盯市：非调仓日持仓不变，按当日收盘价逐日计算 nav。禁止用周收益平摊到 5 个交易日。
4. 不可成交：调仓日若标的停牌，顺延至下一交易日；涨停时买入顺延，跌停时卖出顺延。记录顺延次数。
5. 成本：买入卖出佣金均万 2.5、单笔最低 5 元；ETF 免印花税；滑点单边 5 bp；闲置资金基准情形 0 收益，货基 1.5% 年化做敏感性。
6. 分批建仓：每次触发按 `batch_frac` 增加目标仓位，累计不超过 `MAX_BATCHES × batch_frac`。卖出同理递减，目标仓位下限 0。
7. 年化常数：全脚本统一 √252，与 A 的 P0-A2 修复结果一致。
8. 口径标注：JSON 的 meta 中写 `nav_method: "daily_mark_to_market"`，与旧平摊口径明确区分。

## 六、脚本内门槛判定

单标的 PASS 需同时满足：

| 门槛 | 条件 |
|---|---|
| 样本外不劣于买入持有 | `oos.total_multiple >= buy_hold.oos.total_multiple` |
| 回撤更小 | `oos.mdd < buy_hold.oos.mdd`（回撤取绝对值） |
| 安慰剂 | `placebo.total_multiple_pct >= 0.90`（主统计量，与冠军因子修复前后可比；夏普分位仅作辅助报告） |
| 参数邻域稳健 | `frac_better_than_bh >= 0.60` |

汇总 PASS：`symbols_passed >= 2` 且 `direction_consistent == true`。否则 FAIL，需在报告标注失效原因。

补充一：安慰剂只对基准参数做单次判定，不涉及多重比较。若后续对 75 组参数逐一做显著性检验，须按检验次数做 Bonferroni 或 FDR 校正，禁止直接套用 0.90 门槛。

补充二：趋势市年份（如 2019 至 2020、2024）的逐年表现单独列出，均值回归在单边趋势市失效的影响如实标注，不做全局结论掩盖局部失效。

## 七、与引擎修复（P0-A2）的关系

1. 本脚本独立于 cs_flex，不复用其平摊逻辑。cs_flex 是为股票横截面选股设计，F2 是单标的择时仓位，强行复用会引入不匹配的持仓期假设。
2. 复用 `xbx_engine.metrics` 前，A 需确认其年化常数已从 √244 统一为 √252。若未统一，F2 脚本内部自行按 252 计算并在 meta 标注。
3. A 完成 P0-A2 的逐日 mark-to-market 修复后，可用同一套 `mark_to_market` 思想校验 F2 的净值序列，确保没有隐性平滑。
4. 若 A 在修复中发现 metrics 接口变化，按本规格第五节 JSON 结构为准调整，保持字段稳定以便后续 B 写事实源、E 做独立审查。
5. 所有结果禁止引用旧冠军因子平摊口径的夏普 5.62、日胜率 65.6% 等数值。
