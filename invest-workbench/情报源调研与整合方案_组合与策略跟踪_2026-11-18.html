2.1 snowball-monitor — 存在，但GitHub活跃度极低

核实快照 仅学习价值

GitHub REST API：stars 0 / forks 0 / issues 0；创建 2026-02-04，最后 push 2026-03-25（约 8 个月未更新）。MIT，单文件 fetch_rebalancing.py + 一个 workflow。

它做什么

GitHub Actions 云定时抓 /cubes/rebalancing/history.json?cube_symbol=&count=1 → Upstash Redis 去重归档 → Bark 推 iPhone。
机制源码确认的细节
分时段频率run.yml 4 条 cron（均 UTC）：7,27,47 * * * 1-5（每20分）；17,37,57 1-7 * * 1-5（亚洲时段加密到10分）；38,43,48,53,58 6,7 * * 1-5（北京14:38起每5分）；7 0,6,12,18 * * 0,6（周末保活）。README 说"14:45 起 5 分钟"，源码实际更早更宽。
去重状态表 xueqiu:status:last_ids 存 {ZH: {id, status}} — id + status 双字段；历史表 xueqiu:history:{symbol} 用 LPUSH + LTRIM 0 199 保留 200 条。
推送逐股 {action} {name}: 5%→6% (+1%)，仅 abs(change)>0.01 入列；created_at/1000 +28800 强制转北京时间；id 变 或 同 id 状态变（pending→success）都触发。
Cookie 告警HTTP 400/401/403 判失效 → Bark 告警，COOKIE_ALERT_INTERVAL=86400（注释写3天，实际1天）冷却 → sys.exit(1) 让 Action 失败。无重试/退避。

2.2 xueqiu-mcp — 存在，3 个组合工具，鉴权设计值得抄

核实快照 很新·低星

stars 1 / forks 0；创建 2026-08-13，最后 push 2026-09-09。TypeScript / Node ESM（源码要求 Node 20+），32 个工具，LobeHub 收录版本 2.0.0。

组合相关工具

get_user_cubes → /cubes/list.json
get_cube_holdings → /cubes/rebalancing/current.json
get_cube_rebalancing → /cubes/rebalancing/history.json
注：第3个端点与 snowball-monitor 完全相同
机制源码确认的细节
三级鉴权环境变量 XUEQIU_TOKEN → 本地 cookie 文件（~/.config/xueqiu-mcp/cookies.json，扫码登录）→ 内存匿名 token（GET /about 取 Set-Cookie，有效期 23h）。写工具走 requireLogin()；三个组合工具是公开接口，匿名可读。
登录态判定解 xq_id_token JWT 的 payload.uid：匿名 uid=-1 被拒，需正整数 + 未过期 + u===String(uid)。这套判定思路可直接用于排查 TSP 的 MCP 授权问题。
限流/熔断MIN_REQUEST_INTERVAL_MS=1000+500 抖动；429→30s 起指数退避（封顶120s，尊重 Retry-After）；5xx→5s 起；网络→2s 起；400/401/403 明确不重试；连续失败≥5 次熔断 5 分钟。
不可照搬：两个项目都可能跑在云端（GitHub Actions / 你的 WorkBuddy 云会话），而你实测雪球云 IP 会被 BLOCKED —— 照搬等于把已知失败的方案再做一遍。任何雪球抓取都必须留在本机住宅 IP，沿用你现有的 gzip+base64 分片 → TAT 推送链路。

5整合方案（按优先级，均待拍板后实施）

P0 · 先补"别看错数据"（低成本，纯加固）

  1. 统一 freshness 探针：在现有 /api/health 或巡检脚本里，为 sector_rotation / nav / consensus / holdings / pool_daily 各加"最后有效日期 + 落后交易日数"；超过阈值（如行业轮动>2 交易日）在前端顶部黄条提示，并走企微普通提醒（非 P0）。这一步不动任何业务表，纯只读。
  2. 行业轮动恢复或明确下线：现有 18:10 管线已停（停更到 11-10）。要么修数据源（东财 push2 三块 RemoteDisconnected）恢复，要么按 v68 已下线处理、从情绪页移除陈旧展示 —— 二选一，需你拍板。
  3. Cookie 失效告警走企微：把 snowball-monitor 的 check_cookie_status 思路（400/401/403 判失效 + 时间戳冷却）加进 nav_hourly_probe.py / holdings_probe.py，告警发企微普通提醒，避免"Cookie 静默过期 → 数据假新鲜"。

P1 · 抓取链路加固（借鉴两个开源项目，不换架构）

  1. 调仓去重升级为 id+status：现有 push_state.py 是单 SHA 幂等；雪球调仓有 pending→success 状态迁移，内容 SHA 可能不变但状态变了。建议状态键改为 id + status，状态变更也推一次企微（避免漏报"已成交"）。映射自 snowball-monitor 双字段去重
  2. 限流/熔断内置到采集底座：把 xueqiu-mcp 的 MIN_REQUEST_INTERVAL=1000ms + 500ms 抖动、429 退避、400/401/403 不重试、连续失败5次熔断5分钟 抽成公共函数，供雪球/东财/腾讯三条抓取共用。特别解决东财 RemoteDisconnected 时"越重试封越久"的问题。
  3. 腾讯行情升为盯盘主通道：常规快照/K线优先腾讯（免鉴权、批量、限流宽松），东财只拉资金流/龙虎榜/解禁/涨停池等独家数据，请求量压到最低；东财被封时自动切腾讯。沿用现有住宅 IP + TAT 分片链路，不引入新基础设施。
  4. 北京时间显式换算：所有推送时间统一 created_at/1000 + 28800 或等价 TZ 处理，避免云/本机时区错位。

P2 · 按需启用（看你是否需要，不默认做）

  1. iFinD 连接器深用：已接入、边际成本近零，可做组合净值/财务/宏观的交叉校验源；注意 15 分钟延迟，定位"权威补充"而非高频盯盘。
  2. 集思录折溢价数据：若你要看可转债/LOF 套利，需维护 cookie（会过期），且未登录会静默截到 30 条 —— cron 自动化可行性待验证，先人工导出试用。
  3. 把雷达的财联社/金十快讯接进工作台 API：它们已在 radar.sqlite3 里，复用即可补强资讯单一问题。
  4. 一致预期/研报正文：需付费数据源（如理杏仁/机构接口），先明确预算与用途再评估，不主动推进。

明确不做（与既定方向冲突）

  • 不做 任何模拟盘/跟单：东财妙想、聚宽/米筐/BigQuant 模拟盘、且慢/帮你投一键跟投 —— 你已明确否决。
  • 不做 GitHub Actions / 云端直连雪球抓组合 —— 云 IP 必被风控，且高频加密（5分钟）与你"单轮>16只 BLOCKED"结论冲突。
  • 不引入 Upstash Redis —— 与现有 SHA 幂等/本地 JSON 重复，徒增外部依赖与密钥面。
  • 不改 现有 gzip+base64 分片、TAT 推送、chown、pool_daily 重建、企微 P0 FIFO、条件单三件套 —— 生产已验证，两个开源项目不涉及这些。
