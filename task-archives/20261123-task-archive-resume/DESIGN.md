# 第一性原理分析与对抗式审查：20261123-task-archive-resume

## 一、第一性原理：续接任务到底需要什么

跨机器、跨智能体续接失败的根源在于任务状态只活在会话内存里，没有被物化成独立文件。因此必要条件有八项：

1. 目标与边界：要交付什么，什么不算在内。
2. 已定决策：用户拍板过的内容，不能由新智能体重选。
3. 进度状态：已完成、进行中、阻塞分别是什么。
4. 待办事项：下一步具体做什么，带 ID 与状态。
5. 材料：文件、配置、文档、链接，且不依赖原机器绝对路径。
6. 可移植性：所有内容必须以文件形式存在，与会话、智能体、模型无关。
7. 可验证性：接收方能确认没有拉漏或拉坏，所以需要清单与逐文件校验。
8. 安全性：公开仓库不可出现密钥；凭据必须由新环境重新提供。

由此推出架构：GitHub 公开仓库作为权威源（raw 链接任何机器可读），资料库作为可读镜像与交叉校验，MANIFEST.json 作为完整性契约。

## 二、对抗式审查：风险与更稳实现

| 编号 | 风险 | 后果 | 缓解措施 | 落地位置 |
| --- | --- | --- | --- | --- |
| R1 | 令牌随归档进入公开仓库 | 账号被滥用 | 显式脱敏清单，凭据文件不归档；config 只写约定 | SKILL.md 硬约束、SKIPPED.md |
| R2 | 新机器无法访问资料库 | 无法恢复 | GitHub raw 为权威源，资料库仅镜像 | RECOVER.md 第 6 步 |
| R3 | 新机器未安装恢复技能 | 命令失效 | 一键提示自包含；技能副本随包分发 | RECOVER.md、files/skills/ |
| R4 | 上下文未完整物化 | 新智能体理解偏差 | 四份核心文档强制写入，CONTEXT 区分用户要求与助手选择 | CONTEXT.md、STATUS.md |
| R5 | 大文件超出 API 限制 | 同步失败 | 超过 5 MB 跳过并记入 SKIPPED.md | SKIPPED.md |
| R6 | 重复归档产生多份副本 | 版本混乱 | 固定任务 ID 目录，脚本按 sha256 增量覆盖 | pack_task.py、同步脚本 |
| R7 | 待办无法跨智能体迁移 | 进度丢失 | TASKS.md 保留 ID 与状态，恢复方用待办工具重建 | TASKS.md |
| R8 | 中文路径编码失败 | 上传报错 | 复用已验证的 quote 编码同步脚本；raw 清单里的 path 逐项编码 | sync_ai_archive_auto.py、fetch_task.py |
| R9 | 配置文件夹带密钥 | 隐性泄露 | 不自动复制 mcp 配置，只写脱敏后的约定文档 | config/README.md |
| R10 | GitHub API 限流或写入失败 | 误报成功 | 必须核对 `ALL_MATCH = True` 才算完成 | STATUS.md 下一步、SKILL.md 第 5 步 |

## 三、结论

采用「公开仓库为权威源 + 资料库镜像 + SHA256 清单 + 自包含恢复提示」的组合。该方案在资料库不可达、技能未安装、上下文未同步三种最坏情况下仍能工作；代价是多一次清单生成与校验步骤，换取可验证的完整性。
